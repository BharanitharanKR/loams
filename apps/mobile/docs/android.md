# Loams for Android

Plan: AP2 in the main repository (`docs/plans/2026-10-01-ap2-android-compose.md`); design §37 §7. How to run it: [RUNNING.md](RUNNING.md).

## Modules

| Module | Kind | What |
|---|---|---|
| `:core` | Kotlin/JVM | Pairing payload v1, error reasons, `DecisionClaims` canonical JSON and JWS assembly, decision rules, the watch state machine with resume and back-off, HPKE unsealing (Tink), JWK thumbprints, PKCE |
| `:proto` | Kotlin/JVM | Generated protobuf-javalite messages and connect-kotlin clients (committed; see [protos.md](protos.md)) |
| `:transport` | Kotlin/JVM | Connect clients over OkHttp (Connect protocol, binary codec, GET for reads, no stream deadline), TLS trust (pinned SPKI or system CAs, hostname always checked, no redirects), the instance identity check (instance id plus `jkt` in the JWKS), the OAuth token endpoint, QR pairing |
| `:conformance` | Kotlin/JVM tests | The network layer against a live mock: QR pairing, signed decisions reaching the stream, step-up, drop and resume, sealed push round trip, an endpoint catalogue |
| `:data` | Android library | Keystore keys (`decide-<instance>` behind biometrics for every use, `dpop-<instance>` without), BiometricPrompt signing with a CryptoObject, AES-GCM Keystore encryption, the session store |
| `:push` | Android library | FCM registration stub, per-instance HPKE keys, unseal-and-display, notification channels |
| `:app` | Android app | Compose UI: welcome (QR, pasted payload, typed code with fingerprint check, Authentik sign-in, demo), approvals, status, settings |

The JVM modules hold everything that can be tested without a device, so `./gradlew :core:test :transport:test` runs on any machine with a JDK, and the conformance suite needs only the Go mock.

## Rulings made during execution (AP2 Task 0)

| # | Ruling | Why |
|---|---|---|
| E1 | Generated code is committed instead of generated by a Gradle task | Builds need no `buf` and no network; see [protos.md](protos.md) |
| E2 | An extra JVM module `:transport` between `:core` and `:data` | Connect clients, trust and the token endpoint are JVM code; keeping them off Android lets the conformance suite and the TLS tests run on the JVM |
| E3 | Manual dependency wiring (`AppContainer`) instead of Hilt; no Room yet | A handful of singletons; Hilt and the Room cache (AP2 Task 5) come when the cache does |
| E4 | No `fcm`/`unifiedpush` flavors yet; push is a stub with no Firebase dependency | No Firebase project or store account yet (Q420); flavors arrive with real FCM and UnifiedPush (Q439) |
| E5 | Push sealing binds the instance and notification ids through HPKE `info`, with empty AAD | Tink's public `HybridDecrypt` takes context info only; the binding is equally strong |
| E6 | JUnit 4 rather than JUnit 5 | Robolectric and the Compose test rule run on JUnit 4 |
| E7 | The Compose UI test runs on Robolectric in `test`, not as an instrumented `androidTest` | It runs in `./gradlew test` and in CI without an emulator |
| E8 | QR scanning with ZXing Android Embedded | Works without Google Play services, which the planned `unifiedpush` flavor needs |
| E9 | AGP 9.4.1 with built-in Kotlin, Kotlin 2.4.20, Gradle 9.8.0, compileSdk 37 (AndroidX core 1.19 needs it), targetSdk 36, minSdk 29 | Current stable on 2026-10-02 |

## Stubbed or not yet built

- **Sign-in against a real server.** The pairing grant, the Authentik token exchange and DPoP are the unified auth plan's (Q438); today they run against the mock. DPoP proofs are not sent yet (the `dpop-` key exists).
- **FCM.** `FcmStubRegistrar` returns a fake token; in debug builds, Settings can show the mock's sealed pushes while the app is open. Real FCM needs the Firebase project (Q420).
- **The cache** (AP2 Task 5), **jobs and the inbox screen** (Task 7), **WorkManager sync**, **multiple instances**, **the 6-word fingerprint** (the typed-code path shows the thumbprint in groups of four).
- **Release signing and R8 rules** (Task 10, Q420).
