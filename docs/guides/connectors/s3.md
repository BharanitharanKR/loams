# S3 ★ (and the object-storage family)

The S3 connector is native Rust in `fabric/crates/loams-connector-objects`
(CN2 Task 13, runtime ref `loams_connector_objects::s3`). The same crate serves
Cloudflare R2 and MinIO/RustFS as S3 targets, and GCS, Azure Blob, ADLS Gen2
and SFTP with their own APIs; this page describes what they share. Each of
them has a short page of its own for what differs.

| | |
|---|---|
| Protocol | S3 REST through `object_store` 0.13.2 (`aws`) |
| Source | listing with a high-water key per prefix; S3 event notifications (nightly) |
| Sink | Parquet, NDJSON or raw files, rolled by size or time, deterministic names, conditional publish |
| Delivery | source `at_least_once` into `ingest` (ids stable across re-reads); sink `effectively_once` |
| Real systems tested | RustFS 1.0.1 in PR CI; AWS S3 nightly; MinIO when its `ci-service` image exists |
| Fallback | Iggy's `s3_sink` for the sink (OR-4, `replaced_by: CN2 Task 13`) |

## Config

Secrets are named, never given: `auth.*` holds the names of secrets the
namespace's secret store resolves.

```yaml
bucket: orders-archive
prefix: exports                 # the source lists under it; the sink writes under it
prefixes: [eu, us]              # optional: several prefixes, one source split each
endpoint: https://s3.eu-west-1.amazonaws.com   # RustFS, MinIO or R2: their endpoint
region: eu-west-1
allow_http: false               # plain HTTP to `endpoint`: development stores only
virtual_hosted_style: false
auth:
  access_key_id: s3-key-id      # absent: the pod's AWS credential chain
  secret_access_key: s3-secret
  session_token: null
source:
  decode: metadata              # metadata | bytes | csv | ndjson | parquet
  columns: []                   # csv and ndjson: [{name, type, nullable}], SQL type names
  csv_header: true
  poll_interval_ms: 30000       # absent: one listing, then the source ends
  max_object_bytes: 67108864    # larger objects go to the DLQ as poison
  decode_batch_rows: 8192
sink:
  format: parquet               # parquet | ndjson | raw
  roll_bytes: 134217728         # 128 MiB
  roll_interval_secs: 300       # 5 min
  conditional_put: true
  compression: zstd             # parquet: zstd | snappy | gzip | none
  raw_separator: "\n"
```

Column types use the SDK's SQL type names (see
[schema mapping](schema-mapping.md)).

## Source

One split per prefix. A split's position is the last key whose events the
Fabric acknowledged (the high-water key), plus, while a decoded object is
emitted in several batches, its key, etag and next row, so a restart resumes
mid-object. A listing resumes strictly after the high-water key.

- `metadata`: one `object` event per object, `id` `"<bucket>/<key>@<etag>"`,
  `subject` the key, data `{bucket, key, size, etag, last_modified}`.
- `bytes`: the same event carrying the object.
- `csv`, `ndjson`, `parquet`: Arrow batches (the bulk path, D356) with
  `datacontenttype: application/vnd.apache.arrow.stream` and `id`
  `"<bucket>/<key>@<etag>/<first>-<last>"`.

Keys are read in lexicographic order. **An object written later under a key
below the high-water key is not seen by listing**: write keys that grow (a
date or time prefix), or use event notifications.

Event notifications (`notify` module): S3 notifications through SQS or SNS, or
EventBridge's `Object Created` and `Object Deleted`, become `object` and
`object-deleted` events with the listing's ids. They run nightly against real
AWS; the queue client is the cloud family's (CN2 R13.4).

## Sink

Files are named `<prefix>/<instance>/fabric/<first>-<last>.<ext>`, where
`<first>` and `<last>` are the sink's row sequence numbers (20 digits), and
published with `If-None-Match: *`. Each Fabric batch is first staged under
`<prefix>/<instance>/fabric/_staging/` as an Arrow IPC part that carries the
Fabric position and lease epoch in its user metadata (`loamscheckpoint`); a
file is rolled from the staged parts when 128 MiB is staged or the oldest part
has waited 5 minutes, checked as batches arrive. On restart the sink reads the
newest checkpoint back from the store and the Fabric reader resumes there. A
crash loses nothing and publishes nothing twice; a file already sitting at a
sink name with other content stops the instance rather than being overwritten.

Events are written as rows of the CloudEvents envelope (`id`, `source`, `type`,
`specversion`, `subject`, `time`, `datacontenttype`, `data`, `extensions`) in
Parquet, as structured-mode CloudEvents in NDJSON, or as their data in `raw`.
Arrow batches keep their own schema; a schema change rolls the file.

Give each instance its own prefix: two instances of the same name writing one
prefix are refused at publish.

## Egress

Every connection resolves through the instance's egress check after DNS, and
an endpoint given as an IP address is checked before the first request.
`object_store`'s error messages never carry a URL's query string.
