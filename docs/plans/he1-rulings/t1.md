# HE1 rulings, HE0 Task 1: The apps manifest and compose harness

Rulings made while executing Task 1 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R1.1, R1.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R1.1 | **Every mined application talks to its clickhouse-server through a logging proxy** (`op-chlog`/`chlog`: the pinned Caddy image, `apps/clickhouse/chlog.Caddyfile`, a JSON access log with each request's URL; Caddy redacts `Authorization` and cookies), and `apps.sh dump` merges the settings each request carried into `query_log.tsv` by `query_id` (`scripts/house/http_settings.py`), and appends asynchronous inserts that have no `query_log` row. `query_log.Settings` holds only settings whose value differs from the server default, so a client that sends a default (OpenPanel's `max_http_get_redirects=0`, `input_format_parallel_parsing=1`, `date_time_input_format=best_effort` on inserts; clickhouse-js's `enable_http_compression`) left no trace, and the House refused a setting the mining never saw. The R2.5 dump contract is unchanged. HTTP interface options that are not settings (`query`, `database`, `query_id`, credentials, `param_*`, `wait_end_of_query`, `buffer_size`, sessions, `compress`) are left out. OpenPanel is wired; each other application's compose adds its own `chlog` service (Langfuse, Plausible, Umami, SigNoz, …) and is re-mined | OpenPanel's inserts on the House, HE1 Task 9 | Low: a setting sent only in a request body (none of the mined clients do) is still missed |
